## Gotchas

- subtensor v3.4.6-421 (PR #2781, June 2026) switched emission to price-based: e_i ∝ root_prop_i × SubnetMovingPrice_i × (1 − MinerBurned_i). Raw DynamicInfo.emission / alpha_emission_rate reads 0 between drain events (every pool_snapshots row has 0) — use moving_price (SubnetMovingPrice EMA) as the emission-weight signal, and read MinerBurned + RootProp storage maps for a full estimate. A subnet can be economically zeroed via MinerBurned→1 while SubnetEmissionEnabled stays True (specs/feature-emission-guard-burn-term.md).
- Dereg/slot reuse: netuid is NOT a stable identity. network_registered_at changes when a slot is re-registered (observed netuids 40 and 92 within the window). Key every long-lived record by (netuid, network_registered_at) or a derived subnet_uid; dereg_analysis.reused_slots shows the query.
- Two units conventions coexist: Taostats JSON fields are rao STRINGS (÷1e9), pool_history stores TAO floats; normalise_dynamic_info returns both (total_tao/alpha_in_pool in rao, tao_in_pool/alpha_in_pool_tao in TAO). Mixing them silently produces 1e9 errors.
- pool_history seed era (2025-09-22→2026-04-09) is DAILY at 98 subnets; dense era (2026-04-29→06-19) is ~1-minute at 129 subnets with gaps (04-10→04-21, 05-02, 05-17, 05-21→05-28) and NOTHING after 2026-06-19. Backtest loaders must downsample by bucket (MAX(timestamp) per (netuid,bucket)) and detect the resolution boundary (pool_history_loader.detect_dense_era_start).
- moving_price/subnet_volume are NULL before 2026-05-30 in ledger.db; only data/backups/ledger_backfill.db has them backfilled (hourly buckets) — merge the two.
- Taostats: free tier is ~5 req/min (429 after 5 calls, no rate headers); pool/history/v1 ignores `interval` and only returns daily (~198 days max); the old monthly quota was exhausted; auth header is the raw key under `Authorization` (no Bearer). Pro was $50/mo.
- Public Finney wss all_subnets() can take 30–100s under load; a dead websocket hangs forever without asyncio.wait_for — chain_client wraps reads in 45s timeout and reconnects. Blockmachine quota errors arrive on a LIVE socket ('insufficient compute units') and must trigger endpoint failover, not reconnect.
- Backup: VACUUM INTO on a ~1GB ledger takes ~5 min; do not run it in a systemd start path. pool_history grows ~185k rows/day at 1-min cadence (~40 MB/day); plan retention/rollup from day 1.
- pool_snapshots has no UNIQUE(netuid, ts) — duplicates possible if a backfill overlaps the live writer.
- The archive folder E:\SN_Trader\backtest_archive_20260619\db\ is EMPTY despite README.txt listing DBs there; the actual files are E:\SN_Trader\SubnetTrader\data\ledger.db (= ledger_fresh) and data\backups\*.db. p0_ledger.db has stray -wal/-shm siblings (harmless).
- sn*.json files are single-line minified JSON (~170KB each) — the Read tool cannot open them; parse with python.
- GitHub freshness collector stops on the first 403 (rate limit) and skips the remainder; needs a PAT (5000/hr) and per-repo pacing; 40/129 subnets had no resolvable repo in the 2026-06-02 run.
- Legacy tables (positions, orders, fills, signals, decisions, daily_nav, subnets_snapshot, cooldowns, profiles) are empty and undocumented in models.sql — do not migrate them.
- SDK version pinned to bittensor 10.1.0 in the old repo; DynamicInfo attribute names (moving_price, subnet_volume, network_registered_at, subnet_identity) are SDK-version dependent — re-verify on the new box.
