# [code] spec-coverage-matrix

**Topic:** Map the operator's wanted "subnet investment analyst" features (F1–F8) onto the existing TaoSentinel specs (specs/00–18, binding order 02 › 00 › owner spec) and the built code/DB state on 2026-10-09: which `metric_key`s / endpoints / pages already cover each feature, in which phase, what config/keys it needs, and what is missing. Also extracts the `ts-1.0` constants (pillar weights, normalisers, red-flag gates, tiers, pre-registered evidence gate) precisely enough for a new spec 19 to reference, and the conventions spec 19 must obey.

**Method.** Read-only. Specs read with line numbers (`awk`/`grep`); `research/` grepped for `EMA`, `72`, `band`, `technical`, `moving average`, `upload`, `vision`, `image`, `OCR`, `screenshot`, `multimodal`; the built code grepped for anchors (`app/jobs.py`, `app/features/chain_features.py`, `app/scoring/p1_matrix.py`, `app/storage/catalog.py`, `app/features/normalise.py`, `tests/conftest.py`); `app.storage.catalog` and `app.features.normalise` imported in the project venv to count keys; the SQLite DB opened as `file:…?mode=ro` for index listing and `COUNT(*)` on tables expected to be empty (all were). `.env` not read (key states are taken from `research/03-current-state-audit-2026-10-09.md`, names only). The only file written is this report. Everything not verified here is marked UNVERIFIED.

**Companion:** `research/03-current-state-audit-2026-10-09.md` (service state, saved history, keys) — this report does not repeat it except where a claim here depends on it.

## 0. Headline

1. **Six of the eight features are already designed** inside `ts-1.0` and its API/UI/quant specs; the design gaps are concentrated in **F4 (72-EMA band)**, **F6 (chart upload / vision)** and the *interactive* half of **F7 (adjustable weights)**, none of which appears anywhere in `specs/` or `research/` (§2.4, §2.6, §2.7 below give the grep evidence).
2. **Built today (Phases 0–3):** only the chain data layer and the P1 raw-metric producer (`chain_features`, never run on the real DB — `metric_values` = 0 rows), the registry, and the backfill. GitHub (F1), socials (F2), scoring/ranking (F7), validation/backtests (F8), API/UI (all) are **unbuilt** (Phases 4–12; `tests/conftest.py:150` `BUILT_PHASE = 3`; 36 of 53 jobs unavailable).
3. **F3 (alpha price & market data)** is the best-covered feature at the *storage* level (hourly price/moving-price/reserves for every occupant since 2025-02-13, 5-m candles since 2026-06-19 — to 2026-09-24 only) but has **no API endpoint and no chart** in spec 14: the only chart designed is the composite/Health/Velocity score line (`14:1006`).
4. **F5 (distance from deregistration)** is the most completely specified: `dereg_safety`, `dereg_hazard`, `dereg_risk_flag`, `immune_flag`, `occupant_age_days` (05 §2.4–2.5), the `dereg_imminent` ×0.60 gate (12 §2.8), `dereg_watch` with `blocks_left` and `moving_price_rank` (14 §2.5), and the `death_90d` survival label (13 §2.4). Missing: a stored *continuous* distance (price gap to the pruning threshold, immunity days remaining) for every occupant.
5. **Any scored addition is a new `spec_version`** (12:5, 12:726, 03:2413). The cheapest honest home for the operator's new factors (72-EMA distance, socials-with-YouTube, custom weights) is therefore (a) spec 13's **factor registry** for backtests (chain factors like `px_vs_moving` already live there, 13:71), (b) **evidence keys** (w 0) in 03's catalog for display, and (c) a **shadow spec `ts-1.1`** or a clearly-labelled client-side "exploration" view for weights — never the bot feed (15 §2.4 reads `quality` only; 13:144 `promotable` only for `quality`/`composite_smoothed`).

### 2.2 F2 — Socials (P5 + P6 + appendix)

## 6. Gaps, risks and open questions for the spec-19 author

1. **Three features have no design at all** (F4, F6, F7-weights). Spec 19 must say for each whether it is (a) an exploration surface outside `ts-1.0` (recommended for F4/F7: 13 chain factor + evidence key + client-side pillar re-weighting + shadow spec), or (b) a `ts-1.1` change (new registry row/weights → new `spec_version`, new golden hashes, 03 catalog line, raw-row producer, backtest first per master §10).
2. **F4 definition is operator input**: period unit, source series (`price_bars` 1h closes vs 1d vs chain `subnet_moving_price`), band construction, distance metric (`research/03-current-state-audit-2026-10-09.md:239`). The strongest prior in the corpus is the moving-price ratio `px_vs_moving` (t ≈ +4.1 on the 8-month panel, not significant live, `research/01-factor-validation-tooling.md:53`) — a 72-EMA should be benchmarked against it under 13's gate before it earns weight.
3. **F6 is a new class of input** (user-provided images) with no PIT provenance; it conflicts with "Point-in-time or it didn't happen" (`00:33`) unless stored as evidence notes. The vision model, its price and the `claude-api` guidance were **not checked** here (UNVERIFIED); 10's cost governor group is the only budget hook.
4. **No data since 2026-09-24 and the service is not installed**; any ranking today would be computed on stale history (audit §0, §7). `chain_features` has never run on the real DB; its tier-3 fallback on backfilled-only rows is UNVERIFIED.
5. **No backup exists** (`data/backups/` empty) while 13 requires a snapshot from the newest uncompressed backup (`13:294`); run `backup_daily` before any quant work.
6. **Weights are deliberately frozen** (OECD/JRC priors, `00:196`); IC-weighted re-weighting is a Phase-C decision (`00:196`, master §10). An interactive weight UI therefore must label its output as exploration and must not feed 15 (`15:79-98`) — spec 19 should state this explicitly to avoid breaking the "evidence before capital" principle (`00:32`).
7. **Market-data surface missing in 14**: price/market endpoints and an OHLC chart would be new routes under 14's ownership (02 §A2 `02:25`), so spec 19 either amends 14 or is explicitly granted those routes in 02 §A2.
8. **Forward-only pillars** (P3, P5, P6, most P4) mean any "investment score" that uses socials cannot be backtested honestly for ≥ 90 days after Phase 9 goes live (`00:338`; `13:116-118`).
9. UNVERIFIED items carried from the specs that affect these features: `volume` window (`03:917`), `total_tao_buy/sell_24h` unit (`05:229`), TMC 1h candle 10th element (BUILD-LOG Phase 2 item 7), `price_after` only live (`13:102`), GitHub 304 cost and fine-grained-PAT expiry header (`06:396,418`).
